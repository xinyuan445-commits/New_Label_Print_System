# 部署与维护

更新日期：2026-10-19。本文命令以 `BarcodeLabelGen` 为起点。部署前保留已有数据和配置。

## 1. 两种运行方式

| 项目 | Windows 本机试运行 | Docker |
| --- | --- | --- |
| 入口 | `start.ps1` → `backend/local_server.py` | `compose.yml` → 容器入口 |
| 应用库 | `.local-data/pilot.db` | PostgreSQL 16 持久卷 |
| 会话 | 签名 Cookie，不依赖 Redis | Redis 7 |
| 数据初始化 | `create_all`、补系统规格和初始管理员 | `alembic upgrade head`、`flask seed-admin` |
| Web | 默认 `127.0.0.1:18003` | 宿主机 `127.0.0.1:18003` → Nginx |
| 文件 | `.local-data/uploads`、`assets`、`pdfs` | `/app/uploads`、`assets`、`pdfs` 持久卷 |

U8 SQL Server 是独立业务数据库，两种模式都不能用应用库替代它。不同模式的数据不会自动同步。

## 2. 配置

首次将 `.env.example` 复制为 `.env` 并编辑；已有 `.env` 不覆盖。本次文档维护不修改实际连接配置。

| 配置 | 用途 |
| --- | --- |
| `LABEL_HOSTS`、`LABEL_PORT` | 仅控制本机入口；监听多个 IPv4 时用逗号分隔 |
| `LABEL_ADMIN_EMAIL`、`LABEL_ADMIN_PASSWORD` | 本机初始管理员；只创建缺失账号 |
| `ADMIN_EMAIL`、`ADMIN_PASSWORD` | Docker 的 `flask seed-admin`；密码空值生成随机初始密码 |
| `POSTGRES_PASSWORD`、`SECRET_KEY` | Docker 应用库和会话；上线前替换占位值 |
| `SHARED_TEMPLATES` | `1` 表示模板共用，`0` 按既有授权规则隔离 |
| `COOKIE_SECURE` | Docker 使用 HTTPS 时设 `1`；纯 HTTP 下保持 `0` |
| `TZ` | 容器时区，默认 `Asia/Shanghai` |
| `U8_DATABASE` | 测试为 `ufdata_998_2021`，正式 `ufdata_008_2021` 只读 |
| `U8_BARCODE_ACCOUNT_CODE` | 条码账套段，与目标库独立 |
| `U8_SERVER`、`U8_USER`、`U8_PASSWORD` | U8 连接信息，禁止上传 |
| `U8_ODBC_DRIVER` | 留空自动优先选择 Driver 18，再选 Driver 17 |

本机入口使用 `.local-data/secret.key`，不会直接使用 Docker 的 `SECRET_KEY`。Docker 的端口由 Compose 的 `ports` 控制，`LABEL_HOSTS` 不控制容器端口。

后端还支持 `U8_ODBC_CONNECTION_STRING`，但只有完全未设置 `U8_SERVER/U8_USER/U8_PASSWORD` 三个变量时才使用；空变量也算“已设置”。建议继续使用示例中的分项配置，避免两种方式混用。

## 3. 本机启动和升级

安装 Python 3.12、uv、Node.js 22。只使用网页模板功能时可暂不配置 U8；查询会提示未配置。需要 U8 时安装 ODBC 驱动并填写测试库信息。

```powershell
.\start.ps1
# 修改前端或中文帮助后重新构建
.\start.ps1 -BuildFrontend
```

脚本不清空应用数据；按 Ctrl+C 停止服务。若系统策略限制 PowerShell 脚本，可从本目录执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1`，或手动执行 README 的依赖和启动命令。

内网访问需把服务器实际 IPv4 加入 `LABEL_HOSTS`，并配置防火墙 18003 入站规则。`127.0.0.1` 在员工电脑上表示员工自己的电脑，访问中央服务应使用服务器内网地址。

## 4. Docker 初始化

```bash
docker compose up -d --build
docker compose exec web alembic current
docker compose exec web flask seed-admin
```

容器入口默认执行迁移，失败则不启动业务进程。当前迁移链从 `0001_initial_users` 到 `0015_user_hidden_pages`，包含账号功能权限和菜单显示表。`seed-admin` 创建缺失管理员且要求首次改密，不会重置已有账号。

为避免泄露真实配置，不在共享日志中粘贴 `docker compose config` 的完整展开结果。需要仅检查语法时使用 `docker compose config --quiet`。

已知部署边界：

- 独立发布仓库 `New_Label_Print_System` 的 `.github/workflows/` 位于根目录，可由 GitHub Actions 识别；需查看实际运行结果。在旧的嵌套工作区开发时，上层仓库不会自动运行子目录工作流。
- Docker 镜像不自带本项目构建的 Windows 助手；缺失时安装包接口返回 `assistant_not_built`。先用浏览器打印，或在部署方案中把自建产物只读挂载到 Web 容器的 `/connector/dist/blg-connector-windows.exe`（接口根据当前 `/app/app/routes` 路径计算）；这一步需要单独验证。
- 当前没有 SQLite 到 PostgreSQL 的自动迁移。
- 通用数据集异步批量生成仍依赖 Redis；本机入口跳过的是会话/健康检查，不意味着所有异步作业都不依赖 Redis。
- `0006_asset_sha256` 迁移需要在线查询图片记录并读取磁盘进行回填，因此完整链不支持 `alembic upgrade head --sql` 离线导出。不能把部分输出当作可用的完整建库脚本；新环境使用在线迁移。
- Docker 实际构建、PostgreSQL 在线迁移和客户端硬件打印需要在目标环境验收，本机自动测试不能替代。

## 5. 打印助手

开发机安装 Go 1.25 后执行：

```powershell
.\connector\build-windows.ps1
```

产物为 `connector/dist/blg-connector-windows.exe`。本机服务通过已登录的下载接口把它打包为员工安装 ZIP；员工不需要 Go、Python 或管理员权限。使用本项目构建，不能用旧上游二进制替代定制回执协议。

浏览器打印不要求助手。助手只负责当前客户端的本地队列、打印提交和结果恢复，详细操作见 [客户端打印](client-printing.md)。

## 6. 备份和恢复

本机推荐停机后整体备份 `.local-data`，另行安全保存 `.env`。除数据库、图片和历史文件外，`pdfs/bill-print-runs` 还保存原始打印快照、包和回执状态，补打和异常恢复会用到。密钥也应保留；不得提交上述文件到 GitHub。

Docker 需要 PostgreSQL 一致性备份、文件持久卷及部署配置。Redis 任务状态与应用库不同，恢复时先核对未确认任务，不能直接重新打印。

恢复后依次检查登录、用户权限、模板与图片、生成记录、U8 查询，以及 998 测试打印/登记。备份应包含所用提交版本；目前没有内置自动备份或一键恢复工具。

## 8. 常见故障

| 现象 | 检查方向 |
| --- | --- |
| 换电脑模板不见 | 是否迁移了 `.local-data`，是否连接了同一应用库 |
| 内网无法打开 | `LABEL_HOSTS`、服务器实际 IP、18003 端口、防火墙 |
| 员工打印机不显示 | 助手是否在员工电脑运行，从桌面本机代理入口进入；不读取服务器打印机替代 |
| `u8_read_only` | 当前为 008，打印与登记被正常阻止 |
| `assistant_not_built` | 服务部署目录缺少本项目 Go 构建产物 |
| 打印后登记失败 | 核对原任务回执并重试登记，不能直接重打 |
| 查到单据但状态待核对 | 历史标签身份缺失或冲突，需人工核对；不能强制当作未打 |
| 修改帮助未生效 | 帮助 Markdown 在前端构建时打包，需重新构建 |
