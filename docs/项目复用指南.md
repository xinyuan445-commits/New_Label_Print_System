# 项目复用指南

基线：2026-10-19，基础版本 0.23.2。本指南用于另一项目或另一台电脑接手 BarcodeLabelGen，无需 AOCI。

## 1. 先选择复用方式

| 方式 | 适用情况 | 需要处理 |
| --- | --- | --- |
| 完整部署 | 保留现有 U8 与打印流程 | 拉取源码，独立配置应用库、U8、文件目录和打印机 |
| 独立服务接入 | 新系统已有门户、业务后端 | 保持标签系统独立部署，通过同源反向代理和会话访问 API |
| 抽取模块 | 只需模板设计、渲染或特定业务能力 | 按下面的依赖清单搬迁，重做目标系统的授权、数据适配和测试 |

建议先完整运行并验证测试环境，再确定抽取范围。当前系统没有通用 API Key、OAuth 单点登录或正式版本化 SDK，不能假设只复制一个页面或传入单号就能完成集成。

## 2. 获取代码和固定版本

独立发布仓库为 `xinyuan445-commits/New_Label_Print_System`，拉取后根目录即标签项目：

```bash
git clone https://github.com/xinyuan445-commits/New_Label_Print_System.git
cd New_Label_Print_System
```

需要仓库访问权限。旧本机工作区可能仍为 `labelPrint/BarcodeLabelGen`，这不改变独立仓库的根目录布局。交接时记录实际使用的提交 SHA；后续升级按提交差异处理，不依赖“最新版本”这个模糊标记。仓库只有源码，模板、账号、用户配置及打印快照要单独迁移。

## 3. 无 AOCI 的开发入口

按顺序读 `README.md`、`项目说明.md`、`docs/README.md`、`AGENTS.md`，再读与改动有关的业务文档和源文件。

- `docs/aoci/*.md` 可以直接阅读，不需要启动工具。
- `aoci*.txt` 和 `.aoci` 是辅助索引，不参与应用加载。
- 不复制本机 `.codex/config.toml`、AOCI 程序、运行日志、收据或恢复状态。
- 保持完整项目副本且以后需要 AOCI 时，安装匹配版本，按实时 Guide 检查路径和基线。
- 抽取部分代码或改变目录结构时，不能沿用原项目的有效索引身份；应为新项目重新建立认知。
- 没有执行 AOCI 维护时，在交接记录中明确索引未校验，不伪称它与源码一致。

## 5. 接口认证和调用顺序

API 根路径为 `/api`。浏览器使用会话 Cookie，没有独立的业务 API Token：

1. 发起安全 GET（如 `/api/me`），接收 `csrf_token` Cookie。
2. POST `/api/auth/login`，JSON 使用 `email` 和 `password`；`email` 也可为普通登录名。请求头携带 `X-CSRF-Token`，与 Cookie 一致。
3. 登录成功会轮换 CSRF Cookie，后续变更请求使用新值，并持续携带会话。
4. 调用业务接口前保留账号功能权限校验；设备 Bearer Token 只用于 `/api/agent/`，不能代替网页登录。

跨域接入不能只加一个 CORS 通配符解决。优先通过受控同源反向代理集成，或者单独设计新认证适配层；不能删掉 CSRF 或放宽后端权限。

常用入口（完整字段以 `routes/u8.py` 和 Pydantic 请求模型为准）：

| 请求 | 用途 |
| --- | --- |
| `GET /api/u8/bill-types` | 类型、常用项与账套状态 |
| `GET /api/u8/bills` | 按类型、单号及日期查询 |
| `GET /api/u8/bills/{type}/{id}/details` | 单据明细；待打印入口还需进度口径 |
| `GET /api/u8/pending-bills` | 首页未打印完成单据 |
| `GET /api/u8/stock` | 库存筛选 |
| `GET /api/u8/reprint?sn=...` | 原标签查询 |
| `POST /api/u8/print` | 准备单据标签 |
| `POST /api/u8/stock/print` | 准备库存标签 |
| `POST /api/u8/reprint` | 准备补打标签 |
| `POST /api/u8/print/{run_id}/complete` | 核对原批次回执并完成登记 |

前端“普通单据空选择等于全部”发生在页面转换层，API 的 `lines` 仍必须是明确、非空的行列表。库存始终需要显式选择。不能通过调用 complete 伪造实际打印成功。

## 6. 模板与变量契约

模板画布协议版本为 1，坐标和尺寸使用毫米。导入导出使用 `.blg-template.json`，可携带图片资源并重映射资源 ID；不要跨数据库直接复制内部资产 ID。

新单据和库存打印的共同变量为：

| 变量 | 含义 |
| --- | --- |
| `{{单据编码}}` | U8 单号；库存为 `YYYYMMDDHH` |
| `{{行号}}` | 原明细顺序号，从 1 开始 |
| `{{物料编码}}` / `{{物料名称}}` | 存货编码和名称 |
| `{{批号}}` | 当前明细或库存的批号 |
| `{{数量}}` | 本张标签数量，按包装方式拆分 |
| `{{单位}}` | 业务单位 |
| `{{sn}}` | 区分大小写的 22 位流水号变量 |
| `{{条码}}` | 五段完整条码 |

`账套名` 目前为项目固定值，用户模板可直接写固定文字。库存另外提供仓库编码/名称、货位编码/名称和规格型号。**单据查询返回某字段不代表该字段已进入单据模板变量**；新增字段须检查 `build_label_plan`。补打能恢复的字段取决于历史三表及保留的本地快照，不能凭空补齐历史缺失值。

## 7. 数据迁移

- 本机到本机：停机后整体备份恢复 `.local-data`，另行安全迁移 `.env`。不要只复制 `pilot.db` 而遗漏模板图片和打印快照。
- SQLite 到 PostgreSQL：目前没有一键迁移。模板可先导出导入；用户、权限、收藏、历史及资源关联需要单独迁移方案。
- U8：连接配置和三表记录属于独立系统，不在应用 SQLite 中；不得用清空应用库来“重置”U8 打印进度。
- 换电脑：本地默认模板、主题、打印机显示/默认设置不会自动跟随；客户端未确认任务和助手账本也需要在原机核对。
- 表结构升级：容器使用 Alembic，当前 head 为 `0015_user_hidden_pages`；本机 `create_all` 只补缺表，不能当作旧列迁移工具。

## 8. 必须保留的规则

008 只读、998 测试写入；普通单据空选择为全部、库存必须选；共用模板与个人常用分开；补打沿用原 SN；原任务确认失败只重试登记、不重新发纸。完整规则见 [业务规则](aoci/business-rules.md)。

当前仍缺少跨任务数量预留、共享模板编辑冲突保护、自动备份和完整硬件验收。补打次数等待供应商确认。新项目不能把这些限制当作已完成能力。
