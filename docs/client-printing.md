# 客户端打印

## 不安装：浏览器打印

1. 单据、存货或补打页的打印机下拉框选择“浏览器打印”。
2. 点击打印，在预览工具栏点击打印图标，选择本机打印机或 Microsoft Print to PDF。
   选择驱动对应标签纸尺寸，缩放使用 100% / 实际大小。
3. 核对输出后勾选“我已确认标签打印完成”，点击“确认已打印”。此时才登记标签。
   取消窗口不会登记；若已经出纸，不要取消后再创建同一批任务。

此方式无需安装。网页不能自动枚举本机队列或确认出纸，靠用户操作和确认。
单张 PDF 默认文件名为 `单号_行号_SN.pdf`；多张标签为同一 PDF，默认单号命名，
浏览器及驱动可能改变默认保存名。需要自动逐张按 SN 保存时使用助手模式。

## 可选：员工电脑安装助手（Windows）

1. 打开系统的“打印机管理”，点击“安装 / 更新打印助手”。
2. 将下载的 ZIP 解压，双击 `install.bat`。无需安装 Python、Go 或管理员权限。
3. 从桌面“标签打印系统”进入并登录。此入口仍连接中央后台。
4. 在“打印机管理”刷新、设置默认和显示状态。打印机需先安装 Windows 驱动。
5. 在单据、存货或补打页选择本机打印机并打印。

选择 Microsoft Print to PDF 后，每张标签保存在**执行打印的电脑**的
`下载/标签打印`，文件名为 `单号_行号_SN.pdf`。补打使用独立子目录，避免覆盖原文件。
物理打印提示“已提交”表示驱动接收任务，不代表已经出纸。

若出现待确认任务，点击“确认打印结果”。确认仅查询原任务并补登记，不会重新打印。
若助手重启或驱动报错后仍无法确认，请先检查出纸和 Windows 队列，再决定结束任务。
不要直接再次打印同一批内容。

## 开发及部署

- 在 `connector` 执行 `./build-windows.ps1`（Go 命令可通过 `-GoCommand` 指定）。
  将 `connector/dist/blg-connector-windows.exe` 和服务一起部署；安装包使用本项目构建，
  不从上游发布下载旧版。该二进制是构建产物，不纳入源码索引。
- 助手仅监听 `127.0.0.1:9110`，安装到当前用户的
  `%LOCALAPPDATA%/LabelPrintingAssistant`，在登录 Windows 后自动运行。
- 桌面入口通过助手转发中央网页和 API，避免内网 HTTP 页面跨源读取 loopback 被
  浏览器策略阻止。相关约束见 [Chrome 官方说明](https://developer.chrome.com/blog/local-network-access)。
  更新服务器地址后需重新下载安装；保持端口 9110 未被其他程序占用。
- 中央服务负责校验单据/库存、生成固定 SN 和打印快照；PNG 按 300 DPI 生成并由
  客户端 Windows 驱动打印，PDF 模式使用保留实际纸张尺寸的逐页 PDF。
- 打印包上限 64 MiB，展开上限 128 MiB；大批次请分批。客户端拒绝未知队列、
  路径穿越和覆盖文件，浏览器访问只允许配置的中央源及助手自身源。
- 客户端任务结果持久化在 `%LOCALAPPDATA%/blg-connector/label-jobs`。
  同一任务完成后重复提交只返回结果；执行中/异常任务不会自动重打。
- 服务端打印批次继续保存在 `.local-data/pdfs/bill-print-runs`，新增 `.zip` 打印包和
  `.client.json` 回执状态。成功回执后才写追溯三表，失败可原批次重试登记。
  补打保留原 SN/条码，只保存本地生成记录，不新增三表、不增加打印次数字段。
- **008 仍为只读，998 才允许测试打印和登记**。客户端打印不会放宽此限制。
  本次验证使用模拟单据和临时 SQLite，未读取或写入真实 U8 数据。
