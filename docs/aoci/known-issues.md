# 当前限制与待办

这里用于区分已实现规则与尚未完成的改进，不自动扩大本次 AOCI 接入任务。

1. 首页已按明细和标签原始数量显示未打印或部分打印；新记录保存单据类型、单据 ID 和明细 ID。历史记录缺少明细身份、同号单据或重复行无法唯一匹配时保留“待核对”，不自动扣减数量。待打印入口在准备时复查余额，但多用户同时准备仍没有跨任务的数量预留。
2. 单据、存货和补打支持无安装浏览器打印及可选 Windows 助手。自动队列发现和直打需要助手；浏览器模式需用户确认完成，无法自动识别取消或实际出纸。真实员工设备和标签机仍需现场验收。
3. 客户端账本防止同一 run 重复派发，回执丢失可恢复，确认后登记幂等且历史不重复。异常或中断的任务需要人工核对；另开新任务、换浏览器或不同用户仍没有业务单据层面的全局防重。
4. 模板共用和自动保存已有实现，多用户同时编辑缺少完整版本冲突保护。已有模板版本历史不能自动防止最后一次保存覆盖。
5. 本地数据已持久化，未完成自动备份与恢复演练。不要把服务重启、源码升级和本地数据目录重建混为一谈。
6. 首页待打印近 30 天，结果和候选有数量上限；追溯历史查询与实际数据规模有关，需要后续评估性能。
7. 补打次数字段明确暂缓，供应商确认表字段与统计口径前不实施。
8. Docker 与 Windows 本机模式的数据库、会话和文件路径不同；没有 SQLite 到 PostgreSQL 的一键迁移。Docker 也不自动带入定制 Windows 助手产物，具体挂载路径需在部署环境验证。
9. 通用数据集异步批量生成依赖 Redis；本机跳过 Redis 会话与健康检查不等于全部功能都无需 Redis。
10. 独立仓库 New_Label_Print_System 可识别根目录 `.github/workflows`；旧嵌套工作区的子目录工作流仍不会由上层仓库自动执行。GitHub CI 的实际状态及目标环境依赖需单独验证。
