# 必须保留的业务规则

以下规则来自用户已确认需求及当前实现。修改对应功能前必须核对源码和测试，不能仅凭历史计划判断已经实现。

## 数据库与输出

- U8 可查询 `ufdata_998_2021` 和 `ufdata_008_2021`。008 为正式账套：当前实现仅查询；物理打印、补打与登记均由 `u8_read_only` 拦截。测试和追溯写入只能使用 998，写入前还检查实际 `DB_NAME()`。不要修改 `.env` 或绕过校验来验证索引。
- `U8_BARCODE_ACCOUNT_CODE` 控制条码中的账套段，与 SQL Server 数据库目标分开。不能因条码前缀为 008 就将写入目标改为 008。
- 单据或库存打印先重新读取业务明细，验证数量与身份，再生成标签计划；模板渲染、打印提交、追溯登记是不同阶段。实际打印交给浏览器电脑的本机助手；Windows 队列接收成功不等于纸张已经出纸。新批次必须收到有效客户端回执才登记；回执丢失按原任务查询恢复，登记重试不再次出纸。
- 打印助手可选：浏览器模式在本机打印对话框选择队列，用户确认完成后才登记；取消不登记。助手模式读取本机队列并直接派发，不回退服务器打印。
- 助手的 Microsoft Print to PDF 使用客户端直接保存路径，单张文件名为 `单号_行号_SN.pdf`。浏览器模式单张提供相同默认名，多张使用单号命名的合并 PDF，实际保存名由浏览器/驱动决定。生成记录下载名仍按业务单据号。

## 单据和待打印

- 常用单据由用户自行选择，按账号持久保存，最多 8 个。首页待打印使用所有支持的单据类型，不受常用单据筛选限制。
- 首页时间范围近 30 天。入库类正数明细需要标签；销售、其他、材料出库负数明细按退回入库处理。
- 待打印按明细所需数量扣减已确认原始标签数量；部分打印仍保留。核对单据类型/ID、明细 ID、料号、批号、仓库和货位；历史记录无法唯一定位时显示待核对。按 SN 去重，原始数量取条码，不取可能已变化的余额字段。补打不增加首次打印进度。
- 调拨、货位调整及形态转换进入待打印判定。调拨/货位调整需要结合 PDA 三表的制单和条码数量事件，判断既有标签剩余数量；整托移动无需新标签，零散拆分需要。不能单凭包装方式是否为数字做判断。
- 盘点单 PDD 按 `CheckVouchs.iCVCQuantity` 实盘数量打印，仅包含大于零的明细；不能使用账面数量 `iCVQuantity`。
- 单据打印未勾选明细时按当前单据全部明细处理；勾选后只处理已选明细。单据项点击直接加载明细，主表与明细左右排列，各自滚动。
- 从首页待打印入口打开时，空选择仅包括可确定的待打印明细，数量默认剩余量；已完成、无需打印、待核对行不自动打印。准备标签前再次核对剩余量，当前不提供跨任务数量预留。
- 包装方式可逐行或批量修改，标签按整包拆分，并由尾数开关决定是否打印余量。数量计算使用 Decimal。

## 库存、补打和模板

- 库存查询支持仓库、货位、料号/名称、批号筛选，只有正数库存及未停用仓库。无货位仓库读取 CurrentStock，有货位仓库读取 InvPositionSum。
- 库存打印必须显式勾选；不能套用单据页的“空选择等于全部”规则。已选明细确认弹窗允许复核与修改打印数量、包装方式。
- 库存标签批号取 `cBatch`；打印单号为当前日期小时 `YYYYMMDDHH`，追溯 JSON 的 orderType 使用 `KC`。
- 补打按原 SN 查询三表，恢复原条码、数量及业务信息；不生成新 SN，不新增初次打印追溯记录。打印次数字段暂缓，等供应商确认后再做。
- 模板按有权限账号共用；常用单据各账号独立。模板数据保存在应用数据库，重启服务不应清空。默认模板属于浏览器中的按用户偏好。
- 模板文本加粗、纸张方向和对象坐标需要在画布、预览与最终渲染之间保持一致；纸张横向布局不等于浏览器显示缩放。
- 管理员分别控制账号页面功能权限与菜单显示。隐藏菜单不自动撤销接口权限；后端必须独立检查功能权限。登录标识允许普通账号名，密码不要求复杂度；密码仍需安全散列。
- 完成通知显示 3 秒并可手动关闭；预览使用弹窗，避免撑高主页面。界面说明使用简短自然业务用语。
